# Task Design

## When to Use

- タスク単位の機能設計書を作りたいとき
- 実装前にインターフェース、責務分割、例外系を整理したいとき
- 実装漏れや設計上の穴を先に洗い出したいとき

## Required Inputs

- 正本の仕様書
- 対象タスク
- 関連する既存コードや既存設計があればその指定

## Procedure

1. 正本の仕様書から対象タスクの責務と完了条件を抜き出す。
2. 変更対象の層、責務分割、入出力、状態、エラー系、テスト観点を整理する。
3. 軽微変更で済む範囲と、重大変更に該当しそうな境界を明記する。
4. 実装前に人が確認すべき判断点を分離する。
5. 文書化する場合は docs/.ai-works に設計書草案を置く。完成済みで current への移動漏れが明らかな場合のみ移動し、報告する。

## Stop Conditions

- 仕様書だけでは責務境界が定まらない
- 外部 I/F や保存形式に影響する可能性がある
- 既存設計と衝突するが、どちらが正本か不明

## Output

- 機能設計書案
- 主な責務分割
- 重大変更の候補
- 実装前の確認事項
