# Requirements To Spec

## When to Use

- 要件整理から仕様書ドラフトを作りたいとき
- 既存仕様への影響や不足論点を先に洗い出したいとき
- 実装前にセキュリティや外部 I/F の懸念を整理したいとき

## Required Inputs

- 人が示した要求
- 対象範囲
- 既存の正本文書があればその指定
- 制約、締切、互換性条件があればその情報

## Procedure

1. 人が示した要求と正本文書を確認し、今回の仕様化対象を限定する。
2. 要件の不足、曖昧さ、矛盾、外部 I/F やセキュリティへの影響を洗い出す。
3. 仕様書ドラフトを、目的、対象範囲、ユースケース、入出力、主要なデータ形式、制約、懸念点の順でまとめる。
4. 仕様確定に必要な確認事項を列挙し、人が判断すべき点を明示する。
5. 文書化する場合は docs/.ai-works に草案を置く。完成済みで current への移動漏れが明らかな場合のみ docs/current へ移動し、必ず報告する。

## Stop Conditions

- 要求だけでは正本との関係が判断できない
- 既存仕様と衝突する可能性がある
- セキュリティや権限条件が不明

## Output

- 仕様書ドラフト
- 不足情報
- 主要論点
- 次に人が判断すべき点
