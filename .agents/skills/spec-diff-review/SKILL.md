# Spec Diff Review

## When to Use

- 差分コードが仕様書に合っているか確認したいとき
- PR 前にバグ、回帰、過剰実装を洗いたいとき
- 指示外の変更や設計逸脱が混ざっていないか見たいとき

## Required Inputs

- 正本の仕様書
- 差分コード
- 必要なら関連する周辺コード

## Procedure

1. 正本の仕様書から、今回の差分が満たすべき要件を抽出する。
2. 差分コードと、責務や契約が変わった周辺コードを一段だけ確認する。
3. バグ、仕様不一致、回帰リスク、テスト不足を確認する。
4. 過剰実装として、指示外のリファクタ、仕様外の機能追加、不要な抽象化、既存設計方針からの逸脱、diff の過大化を確認する。
5. 指摘は重大度順に findings first で整理する。

## Stop Conditions

- 仕様書が不明
- 差分が取得できない
- 期待挙動が曖昧で断定できない

## Output

- findings first の指摘一覧
- 前提や不足情報
- 残余リスクと未確認点
