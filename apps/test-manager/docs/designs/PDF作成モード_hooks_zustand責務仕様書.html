PDF作成View Hooks / Zustand責務仕様書

本書は、PDF作成Viewで使用している hooks と zustand store の担当境界を整理し、 実装者が「どこに状態を置くべきか」「どの hook が何をしてよいか」を迷わないための作業用仕様書である。

対象: apps/client/src/app/renderer/views/createPdf 主題: state ownership 主題: hook responsibility 主題: preview 境界

1. 目的

1-1. 防ぎたいこと

  • 同じ TestData を複数 hook が個別購読すること
  • draft state と取得キャッシュを同じ store に混在させること
  • preview 更新 command が panel / preview 側へ分散すること
  • 一時モック機能が本実装責務に混入すること

1-2. 今回の判断

  • 外部取得データは resource store に集約する
  • ユーザー編集値は draft store を正本にする
  • panel model hook は UI 向け adapter に専念する
  • snapshot 組立と commit は専用 hook に閉じる

2. 全体構造

層 主な担当 代表ファイル やってはいけないこと
Route / View route mode 解決、panel 構成、resource 初期化、route snapshot 保存 index.tsx, routeModeState.ts 個別 UI の細かい編集ロジックを持たない
Resource store TestData / TestDataCategory など外部取得済みデータの共有 useCreatePdfResourceStore.ts ユーザー編集中の正本状態を持たない
Draft store exam / workbook の編集中 state の正本 useExamDraftStore.ts, useWorkbookDraftStore.ts Firestore や IPC を直接叩かない
Panel model hook store から UI 用 adapter を組み立てる useExamPanelModel.ts, useWorkbookPanelModel.ts 重い外部データ取得を始めない
Step2 hook / Step adapter Step2 の編集 command を mode 別にまとめ、Step1 / Step3 の UI 契約は adapter type で表す useExamStepTwo.ts, useWorkbookStepTwo.ts, panelModel.ts route 制御や panel 表示判断を持たない
Preview commit hook snapshot 組立、restoreState 構成、main への commit useCreatePdfPreviewCommit.ts UI の button 配置を持たない
Preview panel side read、asset request、render 前後の patch 管理 createPdfPreviewOrderStore.ts, useCreatePdfPreviewController.ts snapshot の業務組立をしない

3. Route とパネルの責務

経路 表示する主パネル creationType 備考
/createPdf/main MainPanel exam 暫定モック用。preview 更新 button と自動 commit をここに閉じる
/createPdf/exam ExamPanel exam 本実装側 UI。モック用 preview 更新 UI は置かない
/createPdf/workbook WorkBookPanel workbook 問題集モード本体
重要: main は route mode であり、業務契約上の creationType ではない。 creationType は引き続き exam または workbook のみを使う。 これを崩すと preview IPC 契約や保存契約へ波及する。

4. Zustand Store 対応表

store 正本として持つもの 読む代表 hook / component 持ってはいけないもの
useCreatePdfViewStore route 共通の軽量状態。creationType、grade、title、出力先、preview issue の公開正本 index.tsx, 各 panel model, alert 判定, preview controller 巨大 TestData 本体、preview snapshot 本体
useCreatePdfResourceStore 外部取得データ。TestData、TestDataCategory のキャッシュ useCreatePdfPreviewCommit, useExamStepTwo, 今後の category UI 編集途中の draft、UI dialog の開閉状態
useExamDraftStore exam モード編集中の正本。basic / stepTwo / table / stepThree / meta useExamPanelModel, useExamStepTwo, mock preview controller 他 route の共有キャッシュ、preview asset 状態
useWorkbookDraftStore workbook モード編集中の正本。basic / stepTwo / table / stepThree / meta useWorkbookPanelModel, useWorkbookStepTwo TestData キャッシュ、preview DOM patch キュー
createPdfPreviewOrderStore previewPanel が描画するための order / session / patch queue / sessionIssues useCreatePdfPreviewController, previewPanel.tsx TestData、draft 正本、画面編集 command
補足: preview 関連 state は用途ごとに分かれている。 共通 UI から参照する preview 健全性の公開正本は useCreatePdfViewStore が担当し、 previewPanel の描画順序や patch queue、session 内 issue は createPdfPreviewOrderStore が担当する。 useCreatePdfPreviewController は両者の橋渡しとして、order store の状態を view store へ投影する。

5. Hook 対応表

hook 担当責務 依存してよいもの 依存してはいけないもの
useSyncCreatePdfTestData grade に応じて TestData / TestDataCategory を取得し、resource store へ同期する Firestore hook、preload API、resource store action panel UI の step 状態、button 配置
useCreatePdfTestData 単純な TestData 取得 hook。resource store 同期用の下位 hook typed firestore handler draft store の編集 command
useCreatePdfPreviewCommit snapshot builder 呼び出し、restoreState 構成、commit 実行 view store、draft store、resource store、image asset hook button mount 位置や mock route 判定
useExamPanelModel exam 用 adapter の組立、dirty 導出、grade 変更 dialog command、previewHealth 導出 exam draft store、view store selector、useExamStepTwo Firestore 直接取得、preview commit 実行
useWorkbookPanelModel workbook 用 adapter の組立、dirty 導出、grade 変更 dialog command、previewHealth 導出 workbook draft store、view store selector、useWorkbookStepTwo TestData 取得、previewPanel 制御
useExamStepTwo exam Step2 編集 command。frame 条件、section 更新、dirty key 更新 exam draft store、resource store route 遷移、Dockview 制御
useWorkbookStepTwo workbook Step2 編集 command。カテゴリ条件、行編集、dirty key 更新 workbook draft store 外部取得キャッシュの初期化
useCreatePdfPreviewController previewPanel 側で read、必要画像抽出、asset request、patch queue 追加、currentPreviewState 更新 createPdfPreviewOrderStore、asset cache、view store action 業務用 snapshot 組立
補足: 専用の Step1 / Step3 hook は廃止済みで、UI 向け契約は panelModel.ts の adapter type に集約している。処理の実体は useExamPanelModel / useWorkbookPanelModel が組み立てる。

6. データフロー

  1. index.tsx が route mode を解決し、activeGrade を決める。
  2. useSyncCreatePdfTestData が activeGrade に応じた TestData / TestDataCategory を取得し、useCreatePdfResourceStore に同期する。
  3. 各 panel model / step hook は draft store を正本として編集し、必要に応じて resource store を参照する。Step3 adapter へは previewHealth だけを渡す。
  4. useCreatePdfPreviewCommit は draft store と resource store を読み、preview snapshot を組み立てて main へ commit する。
  5. createPdfPreviewOrderStore と useCreatePdfPreviewController は updated 通知を受け、キャッシュ read と asset request を処理し、order store の sessionIssues を useCreatePdfViewStore.currentPreviewState へ投影する。
  6. PreviewPanel は order store の snapshot を描画する。
設計ルール: 「取得済み外部データは resource store」「ユーザー編集中の正本は draft store」「preview 表示順序は order store」に分ける。

7. MainPanel と preview 更新起点の位置づけ

MainPanel は現時点でも exam 系 hooks と previewPanel の局所確認用モックであり、 本実装の正式 panel ではない。一方で preview 更新責務の正本は CreatePdfView 直下に置く useCreatePdfPreviewUpdateController に寄せる。

対象 責務 責務外
MainPanel exam hooks の局所動作確認、preview 状態や issue 一覧の暫定表示 preview 更新責務の正本を持つこと
ExamPanel 本実装用 UI モック限定の補助 UI を持ち込まない
CreatePdfView 共通 preview update controller の mount、commit 判定、panel への status adapter 配布 previewPanel の描画ロジックや order store の内部状態を直接持つこと
注意: MainPanelPreviewController を残す場合でも、それは暫定の status 表示や manual refresh UI に留める。 自動 commit の起点判定と in-flight 制御は useCreatePdfPreviewUpdateController に集約し、 panel ごとに個別の listener や useEffect 監視を増やさない。

8. 実装者向け判断基準

8-1. 新しい状態を追加したいとき

  • 外部から取得するデータなら useCreatePdfResourceStore
  • 編集中の入力値なら useExamDraftStore または useWorkbookDraftStore
  • previewPanel の描画順や patch queue なら createPdfPreviewOrderStore
  • route 共通の軽量状態なら useCreatePdfViewStore

8-2. 新しい hook を追加したいとき

  • UI adapter なら panel model hook に寄せる
  • Step2 の編集 command なら mode 別 step hook に寄せる
  • 外部取得の同期なら sync hook に寄せる
  • preview commit は既存 hook に寄せ、panel 側へ分散させない

8-3. 禁止パターン

  • panel model の中で TestData を直接取得する
  • draft store に TestData や category cache を入れる
  • previewPanel 側で業務用 snapshot を再組立する
  • mock 専用 command を ExamPanel / WorkBookPanel に混ぜる

9. 現時点の暫定事項

  • useCreatePdfPreviewRuntimeStore は廃止対象であり、preview 健全性の公開正本は useCreatePdfViewStore.currentPreviewState に一本化する。
  • useSyncCreatePdfTestData は現在、grade 単位で TestDataCategory を全件再同期している。subject 単位の部分 invalidation は未実装である。
  • useExamStepTwo では category cache をまだ本格利用しておらず、現状は mock 用 section 生成が主用途である。
  • /createPdf/main は暫定経路であり、正式仕様として固定したものではない。
